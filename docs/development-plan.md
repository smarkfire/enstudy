## 测试策略（贯穿全程）

### 核心原则
**每个开发任务完成后，必须运行自动测试，测试通过后才能进入下一个任务。**

### 测试分层

| 测试类型 | 工具 | 覆盖范围 | 运行时机 |
|----------|------|---------|---------|
| 单元测试 | flutter_test + mocktail | 算法、工具类、Repository、Service | 每个任务完成后 |
| Widget测试 | flutter_test | 组件渲染、交互行为 | 每个页面/组件完成后 |
| 静态分析 | dart analyze | 类型错误、lint警告 | 每个任务完成后 |
| 集成测试 | flutter_test | 完整用户流程 | Phase 8 |

### 测试命令

```bash
# 运行所有单元测试和Widget测试
flutter test

# 运行指定模块的测试
flutter test test/unit/core/
flutter test test/unit/features/cards/

# 运行静态分析
dart analyze

# 运行测试并生成覆盖率报告
flutter test --coverage
```

### 测试门禁规则
1. 每个任务开发完成后，立即编写对应的测试用例
2. 运行 `flutter test`，所有测试必须通过（0 failures）
3. 运行 `dart analyze`，不允许有 error 级别问题
4. 如果测试失败，修复问题后重新测试，直到全部通过
5. 测试通过后，标记任务完成，开始下一个任务

## 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| OCR识别准确率不足 | 标记内容识别错误 | 提供手动编辑功能，用户可修正 |
| 标记检测算法复杂 | 开发周期延长 | 先支持高亮标记，后续迭代其他类型 |
| 百度OCR/DeepSeek API不可用 | 无法识别图片和智能补充 | 核心功能支持离线手动添加卡片；AI为增强功能，备选通义千问/智谱AI |
| API调用费用 | 长期使用成本 | 百度OCR免费额度1000次/月；DeepSeek价格极低（¥1-2/百万token） |
| Flutter性能问题 | 游戏卡顿 | 使用Isolate、优化渲染、减少重绘 |
| 本地存储空间 | 图片占用过多 | 压缩存储、定期清理缓存 |
| 测试覆盖不足 | 隐患Bug遗留 | 每个任务强制测试门禁，核心逻辑覆盖率 > 80% |
| CORS跨域限制 | Web平台无法直接调用外部API | 配置CORS代理服务转发请求；提供代理地址自定义配置；备选方案使用支持CORS的API端点 |
